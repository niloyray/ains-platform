A · Agent usage in the AI-native loop

#What the platform doesActor
A1Poll every onboarded project by JQL; claim the story (→ Specifying, session comment, state in SQLite)Poller ↔ Jira
A2State machine picks the stage; dispatcher resolves the target, the stage prompt and the permission set, and spawns a fresh Claude Code CLI processstate machine → dispatcher → agent
A3The agent writes its output into the clone: spec.md, plan.md and tasks.md, code and tests, or a PR reviewagent → workspace
A4Model calls go through the Claude Code CLI on the Max subscription; the orchestrator never calls a modelagent ↔ Claude Max
A5Push the branch, open or update the PR, mark it ready; after human G3 approval and green CI: squash mergeorchestrator → target repo
A6PR watcher sees a ready PR (or a Human-lane PR labelled ai-review) and spawns the review agent, which posts a PR review and never mergestarget repo → orchestrator → agent
A7The PoC's thin workflows call the reusable ones, which call back to Jira: Code Review with PR link, Staging, Done; Automation's intake-ack commentActions → Jira
