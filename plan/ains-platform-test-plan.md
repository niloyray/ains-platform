# AINS platform — Test Plan

**Scope:** every implementation step of the platform, I1 to I19 in section 9 of `plan/ainativesdlc_plan.md`, plus the setup steps 2 to 8 they belong to. One test case table per step, a traceability matrix, and the evidence each run must leave behind.

**Status:** plan only, revision 2, 2026-11-02 (sandbox project only; `ains-poc` is never touched in Phase 1, per plan D15 and D16). No test has been run; nothing has been built.

---

## 1. Test strategy

### 1.1 Levels

| Level | Name | Runs where | Needs | Used for |
|-------|------|------------|-------|----------|
| L0 | static | workstation, `uv run ruff`, schema validation | nothing | every commit |
| L1 | unit with fakes | workstation, `uv run pytest` | fake `gh`, fake `claude`, recorded Jira JSON | every component I2 to I12 |
| L2 | dry-run flow | workstation or container, `ains poll --once --dry-run` on a fixture story | fakes only | the whole state machine end to end, offline, under one minute |
| L3 | container smoke | `docker compose exec orchestrator ains doctor` | Docker, `.env` with real tokens | image, env isolation, tool availability |
| L4 | live smoke | one call each against the real Jira project, the real `ains-poc` repo, one real `claude -p` | real tokens, env flag `AINS_LIVE=1` | clients, agent runner, workflows |
| L5 | acceptance | story `AINSSB-1` in the sandbox through every phase and gate, plus a Human-lane sandbox PR with `ai-review` | everything | step 8, done criteria |
| L6 | credential and billing checks | workstation and container | real tokens | proof that no Anthropic API usage occurs and no secret leaks |

Rule: a step is done when its L0 to L2 cases pass locally and its L3 or L4 case, where one exists, has been run once with evidence recorded. L5 and L6 close Phase 1.

### 1.2 Fakes and fixtures (built in I18, used by everything)

| Fake | What it does | Lives in |
|------|--------------|----------|
| `tests/fakes/gh` | shell script on `PATH` that logs its argv to a file and returns canned JSON for `pr view`, `pr list`, `api`; exit code configurable per call | `tests/fakes/` |
| `tests/fakes/claude` | shell script that asserts the env contains only the allowed variables, writes the files its stage is expected to produce into cwd, prints a Claude Code style JSON result with `total_cost_usd`, `num_turns`, `duration_ms` | `tests/fakes/` |
| Jira recorder | `responses`-style HTTP mocks loaded from `tests/jira/*.json`, recorded once from the real site (keys and emails redacted) | `tests/jira/` |
| fixture story | `tests/fixtures/story_AINSSB-0.json`: a small story with description, lane AI-native, status Ready | `tests/fixtures/` |
| fixture repo | `tests/fixtures/repo/`: a git repo with `CLAUDE.md`, `.specify/`, `.claude/skills/speckit-*/`, created in a temp dir per test | generated by a fixture |
| throwaway target | real repo `niloyray/ains-sandbox` and Jira project `AINSSB`, both created by `ains target add` (T-I16-3), used by every L4 and L5 test, **kept after Phase 1** as the permanent regression target; the second sandbox is the one removed | GitHub, Jira |

### 1.3 Evidence

Every L3 to L6 run appends one line to `docs/test-evidence.md` in `ains-platform`: date, test id, command, result, link or run id. L1 and L2 evidence is the pytest output in the commit message of the step. The plan's status table (section 5 of the plan) references test ids, not prose.
